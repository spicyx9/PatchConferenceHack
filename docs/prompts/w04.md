# w04 : découverte SERP, Facebook Events, routage, rattachement à la conférence

Dossier : backend/app/providers/events/discovery. Bloc : 05-events.md.

Subagents : A SERP + routage, B Facebook, C rattachement, D tests et fixture.

A. SERP (`discovery/serp.py`)
- Construire la liste de requêtes depuis une conférence (nom, ville, dates, sponsors, speakers principaux) selon la liste de 05-events.md. Appeler core.brightdata.serp (JSON Google, country us), 10 résultats par requête, pagination cursor si disponible. Chaque résultat = URL candidate avec snippet, requête d'origine, position.
- Routage (`discovery/router.py`) : par domaine : luma.com ou lu.ma → appeler `providers.events.luma.fetch_details` ; eventbrite.com → eventbrite ; partiful.com → partiful ; facebook.com/events → facebook ; meetup.com → Web Unlocker + JSON-LD Event ; sinon Web Unlocker + extraction JSON-LD `Event` si présent, sinon extraction LLM (OpenAI, schéma strict, `fields_inferred` rempli, confidence < 0.7 → status unknown). Importer les autres providers par import dynamique avec try/except pour ne pas casser si w01 ou w02 ne sont pas encore mergés (fallback : SourceRecord brut).

B. Facebook (`discovery/facebook.py`) : Bright Data dataset gd_m14sd0to1jz48ppm51, collect by URL et discover by page URL (pages des sponsors) et par lieu (San Francisco, dates), limit_per_input 50. Normalize vers Event : offset UTC → fuseau IANA déduit des coordonnées (timezonefinder), isCanceled → status cancelled, usersResponded → capacity.registered.

C. Rattachement (`discovery/link.py`) : `link_to_conference(event, conference) -> (score, signals)` avec signaux mentions_conference (titre ou description, regex sur nom et alias "Universe"), date_within_window (±2 jours), geo_within_radius (8 km), host_is_sponsor_or_speaker (noms depuis fixtures/events-official.json ou graphe si dispo), topic_overlap (embeddings OpenAI text-embedding-3-small entre description et sujets de la conf, cosinus > 0.35), listed_on_aggregator. Score = somme pondérée normalisée (0.3, 0.2, 0.15, 0.2, 0.1, 0.05). Fonction pure, testée.

D. `run(conference)` qui enchaîne requêtes → URLs → routage → rattachement → Events avec conference_link ; dédup conservative (04-engineering-rules.md règle 6) dans `discovery/dedupe.py` (titre normalisé, ±30 min, 500 m ou même organisateur, `ambiguous` sinon) ; Makefile `probe-events-discovery` ; fixture `fixtures/events-discovery.json` (10 events trouvés par SERP avec requête d'origine) ; tests : routeur, link, dedupe.
