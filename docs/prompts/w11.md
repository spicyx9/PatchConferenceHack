# w11 : voyage (itinéraire, trajets, propositions, Gmail, carte)

Dossier : backend/app/travel. Bloc : 11-travel.md, 06-lodging.md, 07-flights.md.

Démarre sur fixtures/stays.json et fixtures/flights.json ; branche les providers quand mergés (import dynamique avec fallback).

Subagents : A trajets, B propositions et budget, C Gmail, D carte, tests, fixture.

A. `travel/routes.py` : aéroport → Fort Mason : SFO (BART jusqu'à Embarcadero puis Muni 30 ou Uber), OAK (BART), SJC (Caltrain) avec tarifs exacts (table statique BART et Caltrain 2026 vérifiée par recherche web, source citée dans le code) et durées ; Uber : estimateur public https://www.uber.com/global/en/price-estimate/ via core.brightdata.unlock si clé, parser, sinon table d'estimation par distance (étiquetée estimate) ; entre lieux : haversine + 5 km/h marche, OSRM public (router.project-osrm.org) pour la durée à pied et en voiture, transit 511.org si clé gratuite sinon estimation. Sortie legs[] {from, to, mode, departure_local, arrival_local, price{amount, currency, status exact|estimate}, provider, url}.

B. `travel/proposals.py` : combine flights.proposals (J-1, J+1, écart > 80 $) et le plan (event à score élevé la veille) → propositions {kind arrive_earlier|leave_later|cheaper_flight, delta_price, reason, affects[]} ; `accept(proposal)` renvoie les nouvelles contraintes pour le replanner. `travel/budget.py` : planned vs estimate, breakdown vol, logement, trajets, billet conf, repas estimés (étiquetés).

C. `travel/gmail.py` : OAuth Google (google-auth-oauthlib, scope gmail.readonly), fichier credentials via GMAIL_CREDENTIALS_JSON, token stocké dans .secrets/ (gitignored) ; recherche `from:luma.com OR from:partiful.com OR subject:confirmation OR subject:itinerary OR subject:booking newer_than:60d` ; extraction OpenAI structured output {type flight|hotel|ticket|event_rsvp, dates, place, amount, currency, reference, confidence} ; écriture dans le graphe via core.store (ATTENDED prevu, Flight et Lodging status confirmed). Sans credentials : fixtures/emails/*.eml (6 confirmations types) avec badge fixture.

D. `travel/map.py` : GET data pour Leaflet : marqueurs (conf, hôtels candidats par price_status, side events du plan, aéroport) et polylignes des legs. `run(plan, flight_choice, lodging_choice)` → Itinerary. Makefile `probe-travel`. Fixture `fixtures/travel.json`. Tests : routes, propositions, extraction mail sur fixtures.
