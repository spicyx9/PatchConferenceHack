# w07 : personnes et entreprises (Smart Networking data)

Dossier : backend/app/providers/people. Bloc : 08-people.md (y compris la section Résultats recherche 6 si remplie), 13-brightdata.md, 09-graph.md.

Subagents : A collecte des noms, B LinkedIn via Bright Data, C enrichissement et sujets, D matching, fixture, tests.

A. `people/collect.py` : agrège les PersonRef depuis les sources déjà disponibles : fixtures/events-official.json (speakers, présence confirmed), fixtures/events-*.json organizers (hosts, confirmed sur leur event), sponsors (Company → présence probable), invités visibles Luma (payload.guests_visible, probable). Si les providers w01/w03 sont mergés, les appeler ; sinon fixtures. Sortie : liste de candidats {name, hint_company, hint_title, presences[]}.

B. `people/linkedin.py` : le matin, `search_scrapers("linkedin")` via MCP ou docs pour relever les dataset ids profils, entreprises, posts et les mettre dans DECISIONS.md et `.env.example`. `find_profile(name, company)` : core.brightdata.serp("\"<name>\" \"<company>\" site:linkedin.com/in") → scorer les résultats (nom exact, entreprise dans le titre, ville SF ou Bay Area) → match_confidence ; < 0.7 → linkedin_url null. `fetch_profile(url)` et `fetch_company(url)` via datasets (scrape_sync, sinon trigger + snapshot, traitement en arrière-plan avec asyncio, premier appel peut prendre 2 min). `fetch_posts(url, limit 10)`.

C. `people/enrich.py` : GitHub API publique pour les ingénieurs (bio, repos, langages) ; Crunchbase ou page portfolio via unlock pour investor flag et INVESTED_IN (best effort, null sinon) ; `topics_from_text(bio, talk_abstract, posts, repos)` via OpenAI structured output sur la taxonomie courte de 08-people.md ; rôles (founder, investor, pm, engineer, devrel) depuis le titre.

D. `people/match.py` : deux étages : présélection déterministe (recouvrement sujets et rôles cibles des Goals, top 50), scoring OpenAI du top 20 (pertinence par objectif, raison en une phrase, phrase d'accroche à partir de talk, posts, entreprise), fallback déterministe sans LLM. Sortie PersonMatch {person, score, reasons[], where[] (session ou side event avec heure et lieu), opener, presence_status, confidence}. Les bonus et malus graphe (MET, CONTACTED, company_coverage) sont appliqués par w09 ; expose une fonction `apply_graph_adjustments(matches, adjustments)` pure. `run(goals, candidates)`. Makefile `probe-people`. Fixture `fixtures/people.json` (120 personnes cohérentes avec events-official et events-luma : chaque speaker, chaque host, 8 investisseurs seed, 15 fondateurs agents IA, 5 PM Copilot) et `fixtures/companies.json` (25). Tests : find_profile scoring, topics, présélection, fallback.

Règle : présence confirmed seulement pour speaker ou host ; tout le reste probable. Jamais de liste d'invités privée.
