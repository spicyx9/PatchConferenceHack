# w10 : Anti-FOMO + Live Replanning (port de re:Invent Pathfinder)

Dossiers : backend/app/agents/antifomo, backend/app/agents/replanner. Bloc : 10-agents-planning.md, 09-graph.md.

Subagents : A port Pathfinder, B Anti-FOMO, C replanner + simulate-change, D tests.

A. Cloner https://github.com/0gulcandogann/reinvent-pathfinder dans vendor/ (lecture). Lire docs/optimizer.md, docs/architecture.md, apps/api/app/optimizer, ranking, explain, mutations. Porter dans `antifomo/optimizer.py` : `optimize(candidates, constraints, original=None) -> Plan` (sélection globale sous contraintes : chevauchement avec trajet, max par jour, créneaux bloqués, items fixés, budget ; si `original` fourni, pénaliser chaque changement pour un replan à changement minimal, idée ConferenceScheduler `original_schedule`) et `explain(plan)` (pourquoi chaque item, alternatives rejetées). PuLP ou OR-Tools si le port est trop long : documenter dans DECISIONS.md. Interface identique à celle attendue par w09 (`agents/planner/plan.py` importe `optimize` depuis antifomo si disponible).

B. `antifomo/conflicts.py` : paires en conflit (graph.queries.conflicts ou calcul local sur fixtures), pour chaque paire : U des deux, personnes cibles confirmées et probables, sujets, trajet, nouveauté, popularité (registered), verdict, "ce que tu rates", alternative (after party, autre créneau de la personne cible). Sortie Verdict {a, b, chosen, margin, reasons[], missed[], alternative}. Texte par OpenAI à partir du breakdown, jamais le verdict lui-même.

C. `replanner/events.py` : types de changement (new_event, time_change, sold_out, cancelled, venue_change, person_target_available, meeting_accepted, meeting_declined, flight_delay, user_skipped, new_contact_met) ; `apply_change(change)` met à jour le graphe via core.store, puis `replan(original_plan, constraints)` avec optimize(original=...) ; `diff(old, new)` → {added, removed, moved} avec raisons texte ("Je remplace X par Y. X est complet. Y a deux personnes alignées avec ton objectif. Le trajet ajoute 8 min."). `replanner/scenarios.py` : 3 scénarios de démo sur fixtures (un side event du 28 soir devient complet ; un nouvel event apparaît avec 2 personnes cibles ; un talk est déplacé et crée un conflit), exposés à w12 via `list_scenarios()` et `run_scenario(id)`.

D. Tests : optimize respecte les contraintes, replan change au plus 2 items pour un sold_out, diff correct, verdict déterministe sur fixture. Makefile `probe-agents-antifomo`.
